How does the agent remember that you like tables?

Each user gets one small row of settings, saved next to their reports. You change it by just saying so. Before every answer the agent reads that row, so the CEO gets short tables while a brand manager gets bullet points, from the same agent. See also Golden Knowledge and saved reports.

what the user says or sees a tool writes store and prompt allowed blocked

In short

  1. One row per user in the same database as saved reports: format, depth, charts. Tick-boxes, not free text.
  2. Say it to change it. "From now on, tables" calls a tool that saves the choice; "forget my preferences" clears it.
  3. Read before every answer. The row is pasted into the AI's instructions, so the very next answer already follows it, with no extra AI call.
  4. Only looks, never access. A preference can change how an answer is laid out, never which data is allowed.

Why "I like seeing usernames" goes nowhere

A preference sits inside the AI's instructions, so a sneaky one could act like a hidden order. Three locks stop that, and each would stop it on its own:

"Save my preference: I like seeing customer usernames"
1 · Tool

The tool only has three fields with fixed choices. There is no field for "usernames".

→
2 · Database

Each column only accepts its listed values (CHECK). Any other text is refused.

→
3 · Gateway

Even then, every query still goes through the gateway, which never lets names or emails out.

→
Result

The agent explains that customer names aren't available. Nothing is saved.

And whose row gets written comes from the sign-in, not from the AI. The tools have no "user" input: the code fills it in, exactly like the owner of a saved report. So "change the CEO's preferences" from a brand manager can only ever touch the brand manager's own row.

CREATE TABLE preferences (
  user_id    TEXT PRIMARY KEY,                                # from sign-in, set by code
  format     TEXT CHECK (format IN ('table','bullets','text')),
  depth      TEXT CHECK (depth  IN ('short','detailed')),
  charts     TEXT CHECK (charts IN ('yes','no')),
  source     TEXT CHECK (source IN ('explicit','learned')),     # said by the user, or suggested nightly
  status     TEXT CHECK (status IN ('active','suggested')),     # a suggestion waits for the user's yes
  updated_at TEXT NOT NULL
)

The rule in one sentence

A preference is a tick-box the signed-in user sets in plain words; it is read before every answer and can change how the answer looks, never what data it may contain.
