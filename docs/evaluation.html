How do we know the agent writes the right SQL?

Two checks. Before any change ships, the agent sits an exam built from the analysts' Golden trios, and we count how often its SQL brings back the same rows. After it ships, we watch the LangSmith traces of real use for errors, and an AI judge reads a daily sample. See also Golden Knowledge and user preferences.

offline: the exam online: real traces AI judge pass fail, block

In short

  1. The exam is the Golden trios. Each analyst's question + SQL is a test case. The agent answers without seeing that trio.
  2. Compare rows, not SQL text, on the same day. The data changes daily; the analyst's SQL doesn't go stale. Score: e.g. 26 of 30.
  3. Watch real use. Traces show every rejected or failed query over time; an AI judge checks a daily sample: does the SQL fit the question?
  4. Every bad trace becomes a test, so a fixed bug can't quietly come back.

Example 1: the exam, one case

Question from a trio: "Top 3 brands by revenue last quarter". The agent's SQL looks different from the analyst's, yet both bring back the same rows, so it passes. Comparing the text would have failed it.

-- agent (Golden trio hidden)
WHERE oi.created_at >= TIMESTAMP(DATE_SUB(
        DATE_TRUNC(CURRENT_DATE(), QUARTER),
        INTERVAL 1 QUARTER))
  AND oi.created_at < TIMESTAMP(
        DATE_TRUNC(CURRENT_DATE(), QUARTER))
GROUP BY p.brand
ORDER BY revenue DESC LIMIT 3
same rows? 
-- analyst
WHERE DATE(oi.created_at) BETWEEN
        DATE_SUB(DATE_TRUNC(CURRENT_DATE(),
        QUARTER), INTERVAL 1 QUARTER)
  AND DATE_SUB(DATE_TRUNC(CURRENT_DATE(),
        QUARTER), INTERVAL 1 DAY)
GROUP BY brand
ORDER BY 2 DESC LIMIT 3
Diesel         20,508.87   20,508.87  ✅
True Religion  19,275.34   19,275.34  ✅
Calvin Klein   17,985.75   17,985.75  ✅   → case passes

The trio must be hidden from Golden retrieval during its own test, or the agent could copy the analyst's SQL and the score would be cheating.

Example 2: what the judge catches on live traces

"Revenue last quarter" 
WHERE created_at >= TIMESTAMP_SUB(
  CURRENT_TIMESTAMP(), INTERVAL 90 DAY)

❌ Judge: "last quarter" means Jul 1 – Sep 30, but the SQL takes the last 90 days.

vs
A rejected query 
SELECT city, COUNT(*) FROM users
GROUP BY city

Judge: the rejection was right only if it touched personal data. A safe query wrongly blocked is a false alarm, and it's counted too.

The judge is a different model from the agent, and it sees the question, the SQL and the tool results, not just the final text. Before we trust it, it also grades the exam cases: if it agrees with the row comparison on most of them (say 28 of 30), its live scores count.

The rule in one sentence

No change ships unless the agent, without seeing the answers, still gets at least as many Golden and regression questions right as before, counted by comparing rows, not words.
