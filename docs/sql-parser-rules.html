How does the parser turn SQL into a tree, and how do our rules catch a bad query?

Before any SQL runs, our code turns the AI's text into a tree of labelled pieces, then asks that tree a few yes/no questions in order. The first "no" stops the query, and BigQuery never sees it. See also one query's full journey, brand scoping and what happens when a query fails.

SQL text the AI wrote parse tree check passed check stopped it our code rewrites

In short

  1. A library called sqlglot reads the SQL text and builds a tree: one labelled box (a node) per piece, such as Select, Star (*), Column and Table.
  2. Our checks walk that tree and ask questions such as "is every table one of the 4?" or "is there a * that isn't inside COUNT?".
  3. A "no" calls raise: Python stops right there, the AI gets an Error: … message, and BigQuery is never called.
  4. The checks only read the tree. The text that goes to BigQuery is the AI's own text, rewritten in two places: customer ids become pseudonyms (for everyone), and tables are filtered to the user's brands (for brand managers).

The parser doesn't look anything up and doesn't change anything. It only labels the pieces. The * becomes a node called Star. Nobody has worked out yet which columns it stands for, and nobody needs to: the fact that a Star sits directly under Select is enough to know the query asks for every column, including email.

Same symbol, different parent

The * in COUNT(*) becomes the same Star node. The only difference is the box directly above it, its parent. That's how the rule tells "count the rows" (fine) from "give me every column" (stopped).

The code that stopped it

# step2_personal_data/columns.py: check() reads like a checklist, one named rule per line
def check(self, sql):
    statement = sqlglot.parse_one(sql, read=self._dialect)   # text → tree
    self._require_schema_columns(statement)                  # Q5: trace each column; keep * as written
    _reject_select_star(statement)                           # Q6: stops SELECT * here
    _reject_whole_rows(statement)                            # Q7: a table used as a value

def _reject_select_star(statement):
    for star in statement.find_all(exp.Star):                # every * anywhere in the tree
        if not isinstance(star.parent, exp.Count):           # the box directly above it
            raise QueryRejected("Name the columns you need …")  # stop here

raise means "stop this function now and jump out with an error". In gateway.run, every line after the check (customer pseudonyms, brand scope, byte check, database.execute) is skipped, and the message goes back to the AI as Error: ….

The trap: why expand_stars=False

qualify can also replace * in the tree with the columns it knows from schema.yaml. That only changes the tree, not the text BigQuery runs.

Expansion on (the library default)

  • The tree becomes SELECT id, age, city, …. No Star is left, so question 6 finds nothing.
  • The check passes ✅, but BigQuery still runs the text SELECT * and returns email ❌.

Expansion off (what we do)

  • The tree keeps its Star, exactly as the AI wrote it.
  • Question 6 sees it and stops the query before BigQuery.

The rule in one sentence

The parser only labels the pieces of the SQL. Our checks look at those labels and their parents, and the first "no" raises an error before BigQuery is ever called.
